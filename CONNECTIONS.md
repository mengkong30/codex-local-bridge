# Local connection coordination and settings

Default profile: default; loopback discovery ports 37821–37828. The Figma development manifest explicitly lists these local origins, no external services. A foreign occupant of the first port is skipped. Never accept an unrelated JSON server as a bridge. [Figma network manifest](https://developers.figma.com/docs/plugins/manifest/).

The server holds a per-profile process lock and publishes endpoint/PID/instanceId under LOCALAPPDATA/CodexLocalBridge on Windows (~/.local/state/CodexLocalBridge elsewhere). Concurrent MCP/DSH startups share a startup lock and converge on one server. A live lock owner is not killed. Dead owners are reclaimed; corrupt incomplete locks older than 30 seconds may be reclaimed. Registry entries are verified against live health/instance identity, never treated as proof of a connection. Different lower-case profile names can host separate services on separate ports. Filenames are prefixed to avoid Windows reserved names.

Environment: BRIDGE_PROFILE selects the profile. BRIDGE_PORT forces an explicit port (no fallback); without an explicit profile, an explicitly configured server uses port-NNNNN as its profile. When attaching a client to an automatically selected default service on port 37822, set both BRIDGE_PORT=37822 and BRIDGE_PROFILE=default. BRIDGE_STATE_DIR and BRIDGE_DISCOVERY_PORTS allow isolated fixtures/custom deployments; custom ports also require corresponding Figma manifest permissions.

Figma Settings (from hub or compact strip): automatic discovery / specified port, profile name, save/connect, rediscover, check version, endpoint, instance and package/service/runtime versions. Preferences persist as startup defaults in figma.clientStorage; other already-open files keep their connection. Saving waits for persistence acknowledgment. Switching an idle connection disconnects the old ID and requires a new AI bind; executing/queued/unresolved work blocks switching. Opening settings temporarily expands a compact strip and returning restores its size.

MCP local_figma_settings actions get/configure/check. configure requires mode auto/manual, optional profile and port, and no owned bindings. Client preferences live in the state directory, outside plugin/version cache; upgrades preserve them. Environment selects an explicit profile/port over stored startup preferences. Each binding pins endpoint and instanceId. A replacement server can never inherit the old target; stale writes fail before dispatch. DSH shares discovery through bridge/bridge-discovery.mjs; use --profile or BRIDGE_PROFILE. `settings` reports endpoint/profile/instance/version.

Version checks inspect local package version, service protocol 2, controller/panel/reliability/discovery protocol 1, and Figma runtime v10. They do not claim a newer public/cloud release exists or download one. An incompatible service, ambiguous duplicate profile, missing profile, unavailable port, or stale instance produces a specific recovery message. Each target file still runs its own plugin; the hub lists only connected files in the selected service.

New-file boundary: neither the local Plugin API nor this bridge creates new Figma files. local_figma_create_page is the explicit fallback inside an existing file, requires exclusive file scope, and supports preview/idempotency/undo. Existing pages and AI page bindings are never guessed or retargeted.

Install/update: update the owning personal plugin source and use the host plugin install flow; do not edit version caches. Reopen Figma to load runtime v10. If Figma keeps old network permissions, reimport its development manifest once. Uninstall removes the host plugin through its supported flow; a running local service and preferences are separate state, so stop the identified service explicitly when no work is active and retain/remove preferences only as requested. No Windows shell deletion or unrelated app configuration is part of an upgrade.
